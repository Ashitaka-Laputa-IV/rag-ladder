# M1–M6 里程碑规格

> 六个范式共用同一份语料、同一份切分、同一批问题、同一套指标，只改一个变量。
> 成本按 DeepSeek V4.1 Flash（$0.15/M 输入、$0.60/M 输出）+ bge-m3 / bge-reranker（免费）估算，语料 2,000 篇。

## 总览

| # | 范式 | 锚点 | 只改了什么 | 索引成本 | 查询成本 | 一轮总成本 |
|---|---|---|---|---|---|---|
| M1 | Naive RAG | [arXiv:2005.11401](https://arxiv.org/abs/2005.11401) | 基线 | $0 | 1× | ~$0.3 |
| M2 | Advanced RAG | [Anthropic 2024-09](https://www.anthropic.com/news/contextual-retrieval) + [arXiv:1901.04311](https://arxiv.org/abs/1901.04311) | 加第二路召回 + 精排 + chunk 补语境 | $0（embedding 免费） | 1.2× | ~$0.4 |
| M3 | RAPTOR | [arXiv:2401.18059](https://arxiv.org/abs/2401.18059) | 加摘要树索引 | $1.05 | 1.1× | ~$1.5 |
| M4 | GraphRAG | [arXiv:2404.16130](https://arxiv.org/abs/2404.16130) | 加实体图 + 社区报告 | $11.0（500 篇则 $2.75） | 1–5× | ~$11 |
| M5 | CRAG | [arXiv:2401.15884](https://arxiv.org/abs/2401.15884) | 加检索自评 + 纠错 + 弃答 | $0 | 1.4× | ~$0.4 |
| M6 | Agentic ReAct | [arXiv:2210.03629](https://arxiv.org/abs/2210.03629) / [综述 2501.09136](https://arxiv.org/abs/2501.09136) | 把检索变成多轮动作 | $0 | 3–5× | ~$0.6 |

**M4 占 80% 成本**，所以只有它需要缩语料；其余五个可以放心跑全量。

---

## M1 · Naive RAG（基线）

**机制**：`query → bge-m3 向量 → top-k=5 → 拼 context → 生成`

**实现要点**
- 向量：Faiss / LanceDB，1024 维，cosine
- 不做改写、不做 rerank、不做融合
- 上下文上限写死 `MAX_CONTEXT_TOKENS = 4000`（与所有里程碑一致）
- 输出必须带 `chunk_id` 引用

**预期结论**
- 单跳事实可用，专名/编号/多跳明显差
- 是后面所有"提升"的分母

**风险**：无。这是唯一一个"必须能跑通"的。

---

## M2 · Advanced RAG（hybrid + rerank + contextual chunk）

**机制**：在 M1 上叠三个工程件
1. **BM25（bm25s + jieba）** 与向量并行召回，RRF(k=60) 融合
2. **Rerank**：bge-reranker-v2-m3，召回 50 → 精排 top-5
3. **Contextual Retrieval**：索引期给每个 chunk 生成 50–100 token 的文档内定位说明，拼在原文前再 embed 与建 BM25

**实现要点**
- 中文 BM25 必须 `Tokenizer(splitter=jieba_cut, stopwords="zh", stemmer=None)`，且查询与索引同一实例
- contextual 前缀**不改变 chunk 边界**，`chunk_id` 保持不变，保证可溯源
- 三档消融都保留：`M1+BM25`、`M1+BM25+Rerank`、`+Contextual`，报告里能给三行数
- 免费模型限流：embedding 32 条一批

**预期结论**
- 专名/编号题上 **BM25 单独就能反超 dense**
- rerank 通常是全项目最大单次增益（Anthropic 口径：失败率 5.7% → 1.9%）
- contextual 的增益在长文上更明显，但索引成本是 O(N) 次 LLM —— 本里程碑唯一的 LLM 支出

**风险**：contextual 会让索引成本从 $0 变成"每 chunk 一次 LLM"。2,000 篇 × 5 chunk × ~1,300 token ≈ 13M token ≈ **$2**。可控，但要记账。

---

## M3 · RAPTOR（层次摘要树）

**机制**：叶子 = 同一批 chunk → 聚类（GMM/UMAP）→ LLM 摘要成父节点 → 递归 → 查询时跨层检索

**实现要点**
- 叶子节点复用 `chunks.parquet`，不重新切分
- 聚类规模建议 8–12 个节点/簇，层数 2–3 层即可（2,000 篇不必建很深）
- 检索：collapsed retrieval（所有层一起算相似度）为主，tree traversal 可留作对比
- 摘要 prompt 要求保留实体名与关键数字

**成本**：2,000 篇 ≈ 5,000 chunk → 约 500 次摘要调用 → **$1.05**

**预期结论**
- 全局综述题能显著改善，且成本只有 M4 的 1/10
- 验证"全局问题不一定需要图"这个论点

**风险**：树的质量依赖聚类；类别主题混杂时会出现"什么都没说清"的摘要。需要在 30 道全局题上看人工判断。

---

## M4 · GraphRAG（实体图 + 社区报告）

**机制**：chunk = TextUnit → LLM 抽实体/关系 → 合并 → Leiden 层次社区 → 社区报告 → Local / Global 查询

**实现要点**
- **语料缩到 500–2,000 篇**（成本决定）
- 抽取 prompt 用官方 `<|>` tuple 格式；`max_gleanings=0`（省一半成本），失败再开 1
- 实体合并只做"归一化 name + type 全等"；描述先拼接，不做 LLM 摘要（省成本）
- 社区检测用 `graspologic` 的 Leiden，`max_cluster_size=10`
- 社区报告：`max_length=2000`
- 查询：Local（实体 top-10 + 1-hop + 原文）与 Global（社区报告 map-reduce）都要有，因为两者成本差 10 倍
- **先跑 20 chunk 试点**，量解析成功率；<90% 就先改 prompt，别上全量

**成本**：500 篇 $2.75 / 2,000 篇 $11.0（抽取占 80%）

**预期结论**
- 全局题天花板最高，但索引成本是 M3 的 10 倍
- 单跳题上**可能不如 M1**（有实测：49.3% vs 58.8%）
- 弃答题上 global search 容易硬编答案（实测 19.3% 正确拒答）

**风险**：格式解析失败导致空图；实体匿名化少（维基没问题）；社区数过少会让全局报告空洞。

## M5 · CRAG（自评 + 纠错 + 弃答）

**机制**：检索结果 → 小评估器打置信度 → Correct 直接用 / Incorrect 改写重查 / Ambiguous 两者都做 → 都不行则弃答

**实现要点**
- 评估器不用训练 T5：直接用 DeepSeek 做 3 分类（correct/ambiguous/incorrect），成本极低
- 重查策略：查询改写 + 放宽 top-k，**不接网页**（否则评测不可复现）
- 弃答：置信度低于 τ 输出"无法回答"，τ 在一份独立 dev 集上标定
- **τ 必须同时套用到 M1–M4**，否则弃答那一列不可比

**成本**：约 1.4× （每次查询多 1 次小调用）

**预期结论**
- 无答案题的拒答率从接近 0 提升到 80%+
- 对"检索错了但召回到了"的题有明显修复
- 对本来就检索对的题可能有轻微损害（误判）

**风险**：评估器过于保守会把正确答案也弃掉，必须报"误弃率"。

---

## M6 · Agentic ReAct（多轮检索）

**机制**：`Thought → Action(检索/作答) → Observation` 循环，最多 5 轮

**实现要点**
- 工具只有一个：`search(query)` → 返回 top-5 chunk + 分数
- 强制 `max_steps = 5`，且总上下文 4,000 token（与所有里程碑一致）
- 每步记录 token、调用数、耗时，成本指标单独统计
- 终止条件：模型输出 `FINAL:` 或达到步数上限

**成本**：3–5× 查询（约 $0.6 / 150 题 × 1 范式）

**预期结论**
- 多跳题显著提升（可用 MultiHop-RAG 交叉验证）
- 单跳题**可能变差**（过度检索、上下文污染）
- 平均延迟 2–4×，这是最该在报告里强调的代价

**风险**：轨迹不可控、容易死循环 —— 必须硬性步数上限；日志要能回放每一步。

---

## 公平性纪律（六个共用）

1. **同一份 `chunks.parquet`**（512/64），`chunk_id` 全程不变
2. **同一批 150 题**，同一 judge，`temperature=0`
3. **`MAX_CONTEXT_TOKENS = 4000`** 对所有范式生效，超出截断
4. **召回指标用 `evidence_recall`**（gold chunk 是否进入最终上下文），不用 recall@k
5. **弃答 τ 统一**，同时单独记录"原生弃答能力"
6. **成本三项必报**：tokens、LLM 调用数、P95 延迟
